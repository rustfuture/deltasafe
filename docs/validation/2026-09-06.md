# deltasafe validation — 2026-09-06

This record is a local portfolio validation pass for the protocol-hardening branch. It is evidence for the listed environment and scenarios, not a production security certification.

## Environment

- Host: macOS Apple Silicon
- Rust toolchains: `rustc 1.94.1` and declared MSRV `rustc 1.85.0`
- Source branch: `codex/portfolio-hardening`
- Network: ephemeral loopback TCP listeners

## Automated checks

The following passed with the committed lockfile:

~~~bash
cargo fmt --check
cargo check --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked -- --test-threads=1
cargo +1.85.0 check --locked --all-targets
~~~

The suite reported 14 library tests, 5 integration tests, 5 helper tests, and 1 doctest. The integration tests cover nested and multi-chunk files, empty files, password salt exchange, wrong passwords, existing destinations, corrupt ciphertext, truncated frames, path traversal, and symlink parents.

## Runtime boundary

The transfer tests use real TCP sockets and real AES-GCM encryption on loopback. They do not claim public-network deployment, certificate identity, forward secrecy, durable replay protection across restarts, or hostile-local-filesystem race resistance.

## CLI smoke demo

An actual receiver process was started on `127.0.0.1:23457` with password mode. The built CLI sent `/tmp/deltasafe-demo-source/deneme.txt` and exited successfully only after the authenticated final status. The receiver produced `received_files/deneme.txt`; a byte-for-byte `cmp` against the source passed and reported a 12-byte file. The demo used temporary paths and no public network exposure.
